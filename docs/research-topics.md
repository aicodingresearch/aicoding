# Research Topics

> **我们研究如何更高效、更可信地使用大模型编程智能体，让 AI Coding 从个人工具变成可信赖的组织能力。**

本页整理 AI Coding（Vibe Coding）/ Coding Agent 方向的研究背景、研究对象、核心问题与选题方向——既服务实验室内部的科研讨论与选题规划，也作为对外介绍实验室方向的入口。

本实验室聚焦学术与工程结合，尤其关注企业转向 AI Coding 过程中面临的共性技术问题，而非做纯理论研究。

## 一、背景

2025 年以来，以大语言模型（LLM）为核心的 AI Coding 工具从"代码补全"快速演进到"自主完成工程任务"的 Coding Agent 阶段。Andrej Karpathy 提出的 Vibe Coding 概念——开发者用自然语言描述意图、AI 生成代码、人凭运行结果决定是否接受——已从个人实验变成日常：订阅一个 CLI coding agent（Claude Code、Codex 等）完成开发工作，正在成为开发者的普遍习惯。

焦点随之转向下一阶段：企业与组织的软件开发正被深刻重塑——传统的需求分析、设计、编码、测试、部署流程需要重构，开发者角色从"写代码的人"向"引导并验证 AI 写代码的人"转变。个人用得多与组织用得好之间存在巨大落差，这一落差带来了大量尚未充分研究的技术与工程问题，也为学术研究提供了丰富的切入点。

## 二、研究对象

- AI Coding 工具与系统（Claude Code、Codex、GitHub Copilot、SWE-agent 等）
- 人与 AI 的协同编程交互过程
- Coding Agent 的任务规划、执行、验证与评估机制
- 企业软件开发流程在 AI 介入下的变化与适应

## 三、研究意义

- **工程层面**：帮助企业理解"AI 能做什么、不能做什么"，制定合理的 AI Coding 落地策略
- **学术层面**：为人机协同、软件工程、智能体系统等方向提供新的研究问题和实证数据
- **实践层面**：为个人与团队沉淀经过真实场景检验的 AI Coding 工程实践与开源工具

## 四、核心研究问题

### 1. 可信验证与评测

Coding Agent 完成任务后会给出执行报告，但报告声称的"已完成、测试通过"与实际状态可能不一致；同时，围绕 agent 的实验与评测本身也存在有效性问题。这是 AI Coding 走向规模化落地时的核心信任问题。

重点研究方向：

- **报告可信性**：如何独立于 agent 自身的报告，验证任务是否真正按目标完成？如何检测"声称完成但实际有偏差"的静默失效？
- **完成度度量**：如何定义和度量 agent 产出与原始目标的一致性？验证的成本、覆盖与置信度之间如何权衡？
- **验证闭环设计**：客观 oracle、回归测试、独立评审 agent 等机制如何组合成可复用、可回放的验证流水线？
- **评测基准与协议**：如何为 coding agent 构建可信的评测基准？现有 benchmark 的数据污染、过拟合与区分度问题如何检测和治理？
- **实验有效性**：围绕 agent 的对比实验如何保证结论有效——基线公平性、可复现性、统计有效性，以及"换个基模结论还成立吗"？
- **过度使用与过度发挥**：模型能力过强时可能过度发挥，把简单任务复杂化、让结果偏离聚焦目标；如何识别、度量和约束"用力过猛"？

### 2. 上下文工程

Coding Agent 的效果高度依赖其获取和利用上下文的能力——上下文既是单 agent 表现的瓶颈，也是多 agent 协作与人机交接质量的决定因素。

重点研究方向：

- **上下文组织与检索**：如何从大规模代码仓库中高效提取与当前任务相关的上下文（文件、函数、依赖关系、历史变更）？
- **上下文窗口策略**：在有限的上下文窗口下，如何决定哪些信息进入 prompt、哪些被压缩或丢弃？
- **上下文交接（handoff）**：在多 agent 协作与人机交接中，如何决定传递什么、压缩什么？交接质量如何度量？交接不足与过载分别导致什么失效？
- **跨会话记忆**：如何在多轮交互和多次会话之间保持项目理解的连续性？
- **上下文质量与噪声**：无关或低质量的上下文对 agent 决策的干扰有多大？如何检测和过滤？

### 3. 多 Agent 与人机协作

当单个 agent 的能力边界明确后，多 agent 协作与人的有效介入，共同决定复杂工程任务的完成度上限。

重点研究方向：

- **任务分解与分配**：如何将复杂的工程任务拆分为多个 agent 可并行或串行执行的子任务？
- **协作模式**：多 agent 之间如何通信、共享上下文、解决冲突（如多个 agent 修改同一文件）？
- **质量保障**：如何设计 review agent、test agent 等角色来保障多 agent 协作产出的质量？
- **人的角色与介入时机**：哪些任务适合 AI 主导、哪些必须人工控制？人应在事前（需求约束）、事中（实时审查）还是事后（结果验收）介入？不同介入策略对质量与效率的影响如何？
- **信任与控制**：开发者对 AI 生成代码的信任度如何影响审查行为和最终质量？"不逐行审查"的风险边界在哪里？

### 4. AI Coding 应用

在通用软件工程之外，AI Coding 在具体领域的深度应用本身是重要的方向：领域应用既检验通用方法，也催生领域特有的 harness、护栏与评测需求——每个高价值领域，都值得用 coding agent 重做一遍它的工作流。

实验室**鼓励学生把 AI Coding 工具真正用起来**：面向自己或身边的实际痛点，研发出解决问题的软件工具，并积极参与开源——工具本身就是应用研究的产物，开源社区的使用与反馈则是对工具价值最真实的检验。

**实例：投资研究。** 投资研究是 AI Coding 的一个天然适配领域——这个领域高度侧重信息收集、数据处理、策略开发与验证，而这些工作正是 AI 编程工具的强项：借助 coding agent，个人可以建造并长期运维过去需要一个团队才能支撑的数据管线、point-in-time 数据存储、研究代码库与回测框架，**极大扩展个人能力边界**。

从学术角度看，它同时是一种 **harness 实践**：金融数据工程有领域特有的正确性要求（时间语义、数据版本、会计口径一致性），存在"代码跑通、单测全绿，但研究含义是错的"这类现有软件工程基准不覆盖的语义失效——`test-driven coding agent ≠ research-correct coding agent`。为这类领域约束构建护栏、验证与评测，与第 1 条核心问题（可信验证与评测）一脉相承，且有真实系统作为实验场景。

注：本方向研究的是"用 agent 建造和验证领域工作系统"，不是"让大模型预测涨跌或选股"。适合对投资、金融数据工程等具体领域有兴趣、愿意在真实系统里打磨工程能力的同学。

### 5. 组织级 AI Coding 能力研究

个人用好 AI Coding 靠一个订阅账号和习惯改变；组织用好 AI Coding 则涉及流程重构、方法论演进和协作模式创新——这是以上各项技术问题最终汇聚的落地层。

重点研究方向：

- **传统流程融合**：现有的需求分析、设计、测试、运维流程如何与 AI Coding 工具融合？code review、CI/CD、版本管理等工程实践在 AI Coding 场景下需要怎样的调整？
- **转型风险管理**：转型过程中的技术债务、安全风险和质量退化如何预防和管理？
- **AI Native 工程方法**：如果从零设计"AI 原生"的开发流程，其核心工程原则是什么（如 prompt-driven development、agent-assisted TDD）？如何建立相应的质量标准和评估体系？
- **研发角色与流程重塑**：产品经理、开发、测试、运维等传统角色在 AI Coding 时代如何重新定义？团队协作工具和工作流如何适配"人 + 多 Agent"的混合团队模式？
- **能力度量与分级**：组织的 AI Coding 能力如何评估、分级和持续改进？

## 五、选题原则：与基础模型能力解耦

基础模型每半年即有显著迭代，实验室选题的基本纪律是：**所做工作的价值不因基模能力提升而消失**。我们研究"怎么用好模型"，不与基模能力赛跑：

- 不做基础模型训练（高校算力条件不具备，也非定位所在）；
- 避免垂类模型式风险——通用基模能力覆盖垂类后，多年调优工作可能迅速贬值；
- 上述核心研究问题均满足该原则：无论基模如何升级，验证、上下文、协作与流程问题始终存在，且基模越强、这些问题的工程与研究价值越突出。

## 六、研究平台与实践载体：HALF

HALF（Human-AI Loop Framework）是实验室围绕 AI Coding / Coding Agent 方向建设的基础实验平台，用于支撑人机协同的多 Agent 编程协作、任务分解、Agent 分工、上下文交接、结果追踪和实验数据沉淀。

HALF 不是单纯的工程项目，而是服务于前述研究问题的实验基础设施：

1. **人的介入与控制**：通过人工确认、阶段性审查节点、执行结果追踪等机制，研究人在 AI Coding 流程中的介入时机、控制方式与责任边界（对应「多 Agent 与人机协作」的人侧问题）。
2. **上下文工程**：通过任务上下文组织、handoff prompt、结构化任务记录与历史经验沉淀等机制，研究上下文组织、压缩、传递与复用方法。
3. **多 Agent 协作**：通过 DAG 任务流、process template、dev/test/review/eval agent 角色，研究多 Agent 分工、协作、冲突处理和质量保障机制。
4. **组织级 AI Coding 方法论**：通过真实 Git 工作流、issue/branch/PR 协作、agent 可用性管理等机制，探索企业软件开发流程向 AI Native 模式转型的方法。

## 七、开放实验与公开仓库

实验室的部分实验以公开仓库方式进行，可复核、可复跑，欢迎在入组之前就参与：

- **[Agent Hi Tax](https://github.com/aicodingresearch/agent-hi-tax)**：一句 `hi` 到底消耗多少？对真实 agent harness 的 token、credits、配额与延迟做统一口径、可复核的持续观测。它是「可信验证与评测」问题的一个微型活案例——连最小交互的真实成本，都需要可复核的度量方法才能说清。欢迎按仓库说明提交你所用 harness 的观测数据。
